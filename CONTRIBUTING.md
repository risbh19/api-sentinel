# Contributing

Branch from the current main commit, keep the patch focused, and use a Conventional Commit subject. Follow the setup and verification commands in [development](docs/development.md).

Use the pull request to describe the intended behavior and its acceptance tests. Include test commands, results, security implications and limitations. Link an existing issue when relevant. Review the actual diff. Before squash merging, verify the PR head, a successful executed CI job, resolved review findings and all required approvals. A skipped job leaves the gate pending. Report sensitive issues through [the security policy](SECURITY.md).
